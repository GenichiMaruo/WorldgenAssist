## Latest candidate correctness and transport evidence

`test-artifacts/network-dispatch-gate-20260929-215751-919/summary.json` tested
the Fabric candidate hash above, not the final renamed release archive:

- Six selected reply-session, connection-ingress and batch-dispatch tests
  passed with zero failures, errors or skips. Fabric build and affected native
  transport builds passed. Native runtime/tests were not selected for this gate.
- Installed Fabric Overworld with two owners and a dedicated server limited
  to two logical CPUs matched all **1,802** shared NOISE digests and required
  remotely applied chunks for both owners. Successful owner jobs overlapped.
  Comparison was `COMPLETE`, zero issues; both scenarios cleaned up safely.
- Exercised 276 accepted network ingress results, zero main-route results and
  ten per-owner request batches. Both clients replied directly from workers.
- No decode failure, density mismatch or logged job timeout was found in this
  gate. Cancelled replies were rejected. Server overload/scripted movement
  warnings and offline test account/Realms/OS warnings remain in the logs.

Earlier context-reuse, early-validation, prefetch and adaptive-wait checkpoints
are retained with their exact candidate hashes in `docs/TEST_RESULTS_LATEST.md`.
They are not additional tests of the final release archive.

## Latest candidate performance evidence

`test-artifacts/csb-20260929-220931-467/summary.json` used the same Fabric
candidate hash. Server CPU affinity was mask 3 (two logical CPUs) on a separate
PC; the two clients shared the initiating PC. Overworld seed 8675309, cache
128, prediction and eight validation cells were selected. Each mode had one
excluded warm-up and three measured repeats, with identical coordinates and
1,682 NOISE tasks per repeat. Every client region received all 81 chunks.

| Median metric | Vanilla | Assisted |
| --- | ---: | ---: |
| Target 9×9 NOISE region ready | 11,263.926ms | 7,453.593ms |
| Target 9×9 FULL region ready | 14,575.745ms | 14,844.130ms |
| Target receipt by both clients | 17,435.7368ms | 17,800.9879ms |
| NOISE throughput | 29.4380 tasks/s | 29.5616 tasks/s |
| Whole measured server CPU | 103,328.125ms | 102,296.875ms |
| Tick p95 | 16.9572ms | 18.9669ms |

NOISE readiness improved 33.8%; FULL and receipt did not improve. The small
2.1% receipt difference is descriptive, not proof of a general regression.
There were **20 demand-wait fallbacks** in assisted measured repeats (10, 2, 8).
The paired summary's separate fallback/timeout counters do not count these
short-wait expirations. Three fixed-order repeats do not establish general
speedup or isolate each implementation's contribution. This is not an
alpha.4-versus-alpha.5 controlled comparison. Server/client clock origins
differ, polling is 250ms, and client receipt excludes finished rendering.

## Compatibility and remaining limits

- Protocol 4 is incompatible with alpha.4's protocol 3. All participating
  server/client installations must use matching loader/version JARs.
- Latest changed runtime is verified on Fabric Overworld with two owners.
  Latest Forge/NeoForge candidates built successfully; their new hooks and
  worker-send paths have not been verified by a new native runtime pair.
  Earlier alpha.4 native runtime is historical evidence only.
- A prior Fabric protocol-4 compatible custom-dimension fixture matched
  841 shared NOISE digests and one remote application, on candidate
  `DEFF86143B2F59915AAE17B54FF3628485466348DB009924BD01B8BE4B746E4C`.
  It was not rerun with the latest scheduling/ingress changes. Additional
  dimensions require compatible client-available noise settings. Explicit
  wrappers must actually delegate density generation to vanilla noise code.
  Arbitrary algorithms and server-only noise registries are unsupported.
- Only density sampling is offloaded. Blocks, aquifers, surface/carvers,
  decoration, structures, lighting, FULL conversion, saving and delivery
  still execute on the server. Faster final chunk availability remains open.
- Assistance remains off by default and explicitly discloses the raw seed
  when enabled. Private-seed confidentiality, hostile public-server use,
  long sessions and arbitrary mod/datapack compatibility are not established.
  The 26.2 public-seed transcript fixture is absent from 26.3.
