# Worldgen Assist 0.1.0-beta.1 · Minecraft 26.3

## 日本語

このβ版は、低性能な専用サーバーに信頼できる参加者が接続し、新しい地形の生成を手伝う構成を対象とします。前版からの変更は安定性の検証です。3ローダーすべてで、クライアントのチャンクキャッシュを直接確認し、着地地点を受信してからサバイバルに戻す手順で再検証しました。 Fabric・Forge・NeoForgeの各環境で、同じワールドの再起動後に2人が60分探索し、飛行前後のサバイバル操作、プレイヤーが設置したブロックと保存後の照明を確認しました。

**生成完了までの待ち時間**は、Fabricで過去に実施した比較で中央値 **20.93%短縮**しました。i7-7700Kのサーバーを用意し、別のi7-12700KのPCで2クライアントを動かし、サーバーとクライアントの距離を32チャンクに設定しました。同じMOD・同じ生成設定で支援のON/OFFを切り替え、同じ3領域を実行順を入れ替えて計6組比較しています。必要なチャンクがクライアントに届くまでの時間は **21.20%短縮**、サーバーCPU時間は **19.63%減少**しました。一方、遅い側のサーバーtick時間（95パーセンタイル）は **8.95%増加**しています。受信の計測は描画前に終了します。MOD未導入との直接比較や、各ローダーで得られる改善率は未測定です。

**導入**にはMinecraft 26.3とJava 25が必要です。Fabric 0.19.5 + Fabric API 0.161.0+26.3、Forge 66.0.3、NeoForge 26.3.0.13-betaから、使うローダーの配布用JARを選び、サーバーと参加クライアントを一緒に更新してください。共有プロトコルは14、ネイティブの通信バージョンは6です。支援は既定で無効です。検証に使用した設定は添付の `INSTALL.ja.md` にあります。

完全な地形生成の委託は対応条件を満たすバニラのオーバーワールドに限ります。使用にはワールドのシードを参加クライアントに明示的に開示します。協力者同士が共謀する環境、独自の地形生成器、長期連続稼働は今回の検証範囲外です。

先行試験では、NeoForgeでプレイヤーをサバイバルに切り替えて遠方へ転送した際、着地地点のチャンクが約0.4秒後に届き、体力20のまま1ブロック低い着地を報告した例があります。保存された地形は元の高さでした。今回の着地試験では両クライアントが地形を受信した後にサバイバルに戻しています。受信前の遠距離転送の問題は未解決です。

## English

This beta targets a dedicated server that can share terrain generation with trusted players on more capable PCs. The change since alpha.9 is the stability evidence. All three loader rows come from the final run using the corrected client chunk-cache check and the verified approach to the landing area. On Fabric, Forge and NeoForge, two players explored for 60 minutes after the server restarted the same world. Survival interactions before and after flight, player-placed blocks and saved lighting were verified for each loader.

In the earlier Fabric benchmark, enabling assistance shortened the time for new chunks to reach **FULL by a median 20.93%**. A dedicated i7-7700K server served two clients on one i7-12700K PC at view distance 32. The comparison used the same mod and generation settings, toggled assistance, and covered three regions in both execution orders. Across the six pairs, required chunks reached clients **21.20% sooner** and the server used **19.63% less CPU time**. The 95th-percentile server tick took **8.95% longer**. The receipt measurement ends before rendering. This comparison measures the effect of enabling assistance within the tested Fabric profile.

Use Minecraft 26.3 with Java 25 and the distribution JAR for Fabric 0.19.5 + Fabric API 0.161.0+26.3, Forge 66.0.3 or NeoForge 26.3.0.13-beta. Update the server and participating clients together. Shared protocol 14 and native channel 6 apply. Assistance is off by default. The attached `INSTALL.md` includes the configuration used for measurement.

Complete terrain delegation covers eligible vanilla Overworld generation. Enabling it discloses the world seed to participating clients. The evidence covers trusted players and bounded sessions. Colluding clients, custom generators and indefinite operation remain outside this scope.

An earlier NeoForge trial switched a flying player to survival and teleported them to a distant site. The player reported landing one block low at full health. The chunks arrived about 0.4 seconds after the survival-mode notification, and the saved floor was intact. The final test checks receipt before switching to survival. Abrupt teleports before receipt remain an open case.
