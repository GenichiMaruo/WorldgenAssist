## Source-verified opportunity

Generated26.3 NoiseBasedChunkGenerator.buildTerrain runs private doFill,
buildSurface and generateCarvers sequentially within one NoiseChunk. Section
locks surround doFill. buildSurface uses MaterialSystem, and generateCarvers
can resolve source biomes without a WorldGenRegion when its argument is null.
These observations do not yet prove a private client replica is equivalent.
Verify all private descriptors, prototype construction/height/biome inputs,
fluid-postprocessing representation and native source variants before coding.

MaterialSystem narrows density volumes to the highest filled section. Column
gradients read adjacent in-chunk heightmaps while earlier columns may already
have been modified by badlands/ice extensions. A naive independent surface
point check or an unmodified terrain-height snapshot is insufficient.

## Proposed calculation and bounded transport

1. Server assigns only existing actual/observed eligible owner terrain, using
   the same identity, epoch, deadline, quotas and bounded ahead queue. Initially
   support source-verified stock Overworld noise graphs with empty blending/
   structure contributions and no upgrade/debug mode. Others fall back.
2. Capture the biome source and material graph as well as current noise context.
   The old fingerprint does not independently include these; extend/version it
   and bound any added context message. Avoid repeating a large biome graph in
   every chunk request. Unsupported/missing client registries must decline.
3. Client computes on a private prototype using original pinned terrain/surface/
   carver methods, no server world access, tickets or rendering. Prefer small
   verified invokers over copying the full vanilla algorithm. Keep bounded owned
   worker/result queues and cancellation even for private computation.
4. Return compact choices from a server-defined bounded terrain palette, never
   client-defined block IDs, block entities, arbitrary NBT, entities or world
   operations. Exclude block-entity states and cap palette/volume/decompressed
   bytes before allocation. Fluid postprocessing needs a separate bounded exact
   representation; do not assume one final fluid bit reproduces repeated writes.
   Change the protocol explicitly and test native fragment bounds.
5. At the original terrain runnable start, consume only fully accepted current
   output. A small server-owned applicator checks everything before any write,
   then preserves final section counts/heightmaps/fluid processing. Never retry
   vanilla after partial mutation. Without ready output run original local work.

## Verification hypothesis to prove first

Recomputing a full chunk for every reply would eliminate the benefit. A new
explicit trusted-client audit policy could independently recompute the first
two results of each owner/context, then privately choose whole-chunk audits
with probability1/8. Every result still receives complete envelope, palette,
shape, lifecycle and quota checks. No client can choose whether it is audited.
No output is applied before its assigned audit/acceptance completes.

This changes sampled integrity: it is not proof of every chunk or support for
hostile public clients. It requires a separate operator choice and documented
policy, not silently weakening the old8-cell validation. Verify cold-start,
owner/context resets, randomness, quarantine and cancellation using bounded
private server prototypes and authoritative seed/registries only. Compare final
blocks, heightmaps and exact fluid-postprocessing data against original vanilla.
Keep audit and local fallback costs in performance measurements. Probability,
minimum audits and cost are hypotheses, not established configuration defaults.
